### 1.2 命题内容及答题要求（逐字）

> **命题背景：** 高校科研与研究生培养正面临"科研任务碎片化、工具链割裂、重复性劳动繁重"的普遍痛点。文献调研、数据清洗、代码调试、实验记录、论文润色、专利检索等环节分散在数十个软件与平台之间，研究生和青年科研人员大量时间被低价值的重复劳动占据。《教育强国建设规划纲要（2024—2035年）》明确提出以人工智能重塑科研范式、提升拔尖创新人才培养效率。大模型与智能体（AI Agent）技术的成熟，使"每个科研环节配一个专属AI Agent、多个Agent协同完成复杂科研任务"成为可能，为高校科研助理平台的智能化升级提供了坚实的技术基础。

> **命题内容：** 基于腾讯WorkBuddy或LearnBuddy平台，设计并实现一套面向高校科研场景的智能科研助理平台。平台以"一句话调度、多智能体协同"为核心，将文献调研、数据处理、代码与实验、论文写作、专利与合规检查等环节封装为可编排的专属AI Agent；研究生或科研团队用自然语言下达科研任务后，平台自动完成任务拆解、Agent分工、工具调用与结果汇总，并将过程与成果沉淀为可复用的团队知识资产。

> **答题要求：**
> 1. 技术方案：基于大模型多智能体（AI Agent）框架，构建不少于4类专属科研智能体（如文献调研、数据分析、代码/实验、论文润色与投稿），实现自然语言驱动的任务拆解、多智能体编排（Planning）与工具调用（RAG检索、代码执行、数据可视化等），支持多个Agent协同完成一个完整科研子任务闭环。
> 2. 核心功能：①自然语言科研任务下达与自动拆解；②多智能体分工协同与中间结果流转；③科研知识库的自动沉淀、检索与复用；④论文/专利的合规与查重辅助。
> 3. 性能要求：文献综述类任务的相关文献召回准确率不低于95%；多智能体协同任务的自动完成率（无需人工干预）不低于80%；关键操作响应保持在可接受延迟范围内。
> 4. 交付物：完整项目方案书（含背景分析、需求痛点、技术选型与架构设计、核心创新点、AI算法与智能体编排细节、预期效果评估、商业模式、团队介绍、开发计划）；可演示的原型系统/Demo（需提供演示视频，清晰展示多智能体协同全过程）；技术文档与源代码（若有）。

## 2. 三个硬指标：官方定义逐字引用 + 评测方法核查

### 2.1 指标一：文献综述召回准确率 ≥ 95%

**官方原文（唯一出处，即命题页答题要求 3）**：

> 文献综述类任务的相关文献召回准确率不低于95%

**官方配套评测方法说明：未找到官方口径。**

检索与核查范围：
- 命题详情页全文（无附件、无评分细则）— 无
- 《中国国际大学生创新大赛（2026）评审规则》官方 PDF（10 个赛道分组评审要点，无技术指标条款）— 无
- 《教育部关于举办中国国际大学生创新大赛（2026）的通知》附件 4《产业赛道方案》— 无
- 官方"报名参赛/校企对接流程"页（需学信网登录，未公开）— 无法核实

**口径歧义提示（重要）**：官方用词是"**召回准确率**"，不是"召回率"。
- 若按 **Precision（查准率）= |召回∩相关| / |召回|** 计：可通过提高相关性阈值刷高，较易达标。
- 若按 **Recall（查全率）= |召回∩相关| / |全库相关|** 计：需要人工构建完整的"应召回全集"，成本极高且难证。
- 官方未定义分子分母，**我们必须在方案书中自行定义并写死口径**，同时并列报出 Precision / Recall / F1 三项，防止答辩被追问时无据可依。

### 2.2 指标二：多 Agent 协同自动完成率 ≥ 80%

**官方原文（唯一出处，即命题页答题要求 3）**：

> 多智能体协同任务的自动完成率（无需人工干预）不低于80%

**官方配套评测方法说明：未找到官方口径。**

注意官方自己给了半句括号定义："**（无需人工干预）**"——这是唯一的官方限定词，也是我们必须咬住的锚点。

**"人工干预"的边界官方未定义**，同样需自建口径。建议定义以下 5 类为"干预事件"，任一类发生即判定该任务为"未完成自动闭环"：
1. 人工改写/重发 prompt 才得到可用结果
2. 人工补充 Agent 未能自行获取的数据/文件
3. 人工修正 Agent 产出的代码才能运行
4. 人工接管接管某 Agent 的角色手动产出中间结果
5. 任务中断后由人工重启链路

### 2.3 指标三：不少于 4 类科研 Agent

**官方原文（唯一出处，即命题页答题要求 1）**：

> 构建不少于4类专属科研智能体（如文献调研、数据分析、代码/实验、论文润色与投稿）

**官方配套评测方法说明：未找到官方口径。**

官方举例中"文献调研、数据分析、代码/实验、论文润色与投稿"为 **4 类**。团队方案为 **5 类 + 1 编排中枢 + 1 课题评估器**，在数量上已超额覆盖，无合规风险。

**唯一需要警惕的口径风险**：官方强调"**专属**科研智能体"和"支持多个Agent协同完成**一个完整科研子任务闭环**"。因此 5 个 Agent 各自单跑不算数，必须演示 **≥2 个 Agent 在同一子任务上接力、中间结果自动流转**。这是"4 类"这个指标真正的验收暗门。

### 2.4 第三个性能要求（易被忽略，但同样是官方硬要求）

**官方原文**：

> 关键操作响应保持在可接受延迟范围内

**官方配套评测方法说明：未找到官方口径。** "可接受"未给数值，同样需自建基线（建议 P50/P95 延迟分档报出，并在方案书中明确定义"关键操作"清单）。
