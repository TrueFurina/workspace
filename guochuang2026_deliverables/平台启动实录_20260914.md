## 1. 卡点 6.2 已解：`--agents` 官方字段规范（实测）

### 1.1 官方规范（从 CLI 类型定义 + 真机验证双向确认）

```jsonc
{
  "<agent-name>": {
    "description": "必填。给编排中枢看的能力说明，决定什么时候分派给你",
    "prompt":     "必填。角色系统提示词",
    "tools":           ["可选，工具白名单"],
    "disallowedTools": ["可选，工具黑名单"],
    "model":           "可选，指定模型",
    "mcpServers":      ["可选，字符串引用 或 {name: config} 内联定义"]
  }
}
```

**关键点（和我之前起草的草案有出入，已修正）：**

| 项 | 我之前的草案 ❌ | 官方实际 ✅ |
|---|---|---|
| 顶层结构 | `{"agents": [ {name, role, ...} ]}` | **扁平 map**，key 就是 agent 名 |
| 角色说明字段 | `role` | **`description`** |
| 提示词字段 | `instruction` | **`prompt`** |
| 结构化输出 | `output_schema` + `required_fields` | **没有这个字段**，约束必须写进 `prompt` |
| 编排中枢 | `subagents: [...]` | **不需要写**，中枢靠 `description` 自主判断分派 |

> **`output_schema` 不存在反而是好事**：把防编造字段写进 prompt，而不是做应用层 schema 校验器 —— 这正好落在 R5 红线的安全侧（不自研调度/校验内核）。

### 1.2 文件式 Agent（更适合交付的形态）

除 `--agents` 之外，还支持落文件：

| 位置 | 作用 |
|---|---|
| `.codebuddy/agents/<name>.md` | **项目级**，随仓库提交，团队共用 |
| `~/.codebuddy/agents/<name>.md` | 用户级，仅本机 |

frontmatter 全字段（比 CLI 版更丰富）：

| 字段 | 说明 |
|---|---|
| `name` / `description` / `tools` / `disallowedTools` / `model` / `mcpServers` | 同 CLI |
| `displayName` | 展示名，**可含中文**（"① 文献调研"） |
| `memory` | `user` / `project` / `local` — **Agent 级持久记忆**，跨会话记住科研上下文 ← 答辩加分点 |
| `maxTurns` | 子代理最大轮次 |
| `background` | 强制后台运行 |
| `initialPrompt` | 主 agent 首轮自动注入 |

## 6.5 H 档第一次尝试：**失败**（如实记录，这是资产不是污点）

> 时间：2026-09-14 03:34 ｜ 链路：①→② ✅，③~⑥ ❌ 断链

### 失败 1：权限导致断链

非交互 `-p` 模式下，子 Agent 的 `Bash`/`Write` 需要审批 → ③④⑤⑥ 全部卡死。

```
"blocked_by": "Bash/Write permissions required for code execution"
```

**但好消息是：它没有编数。** 老老实实报了断点就停了——防编造 prompt 起作用了。这正是我们要的行为。

**修复**：加 `--subagent-permission-mode bypassPermissions`（专给子 Agent 用的开关）+ `--permission-mode acceptEdits`。已写进 `run_platform.sh`。

### 失败 2（更危险）：它想造数据

② 数据 Agent 拿不到真实数据集，方案里出现了：

> "基于 Miedema 模型的二元混合焓查找表""添加 ±5~10% 噪声模拟真实测量误差""人为引入 ~3% 缺失值"

**这是合成数据。** 如果让它这么跑出 R²=0.94 写进方案书，评委只要问一句"数据源在哪"，就是**材料造假 → 一票否决**。

**根因**：我的 prompt 里写了「禁静默填充」，却**没写「禁造数据」**。这是个真空地带。

**修复**（已写回 `agents_official.json`）：

| 角色 | 新增红线 |
|---|---|
| ② data | 🔴 严禁生成合成/模拟数据冒充真实公开数据；拿不到就**停止**并写 `not_obtained[]`；合成数据仅可用于方法论演示且必须标 `profile.synthetic=true`，此时下游指标一律不作结论；须写明 `profile.data_source`（名称+URL+许可证） |
| ③ experiment | 🔴 上游数据为合成时必须**拒绝**将其指标作为性能结论，并在 metrics 标注 `synthetic_data=true` |
| orchestrator | 🔴 **链路熔断**：任一 Agent 报合成数据或关键 `not_obtained`，**必须停止后续链路**，禁止在缺真实数据时继续产出结论性指标——「跑完了」不等于「可信」 |

### ✅ 修复已被验证：第 2 次运行，熔断规则真的生效了

修完 prompt 后重跑 H 档（8 分 1 秒），链路走到 ② 拿不到真实数据，它的反应是：
