## 4. 录屏必须捕捉的 5 个画面（缺一影响 L1/L2 判定）

1. 用户**首次输入**完整指令的那一刻
2. 平台**自动拆解 10 子任务 + Agent 分工**展示
3. 每个 Agent 产出出现的时刻（文献列表 / 数据表 / 图 / 代码 / 段落 / 复核 / 汇总）
4. 用户**每次点击或输入**（这是区分 L1 确认 vs L2 修改的关键证据）
5. 最终**汇总产物**页面

> 录屏清晰度必须能看清"用户是否改了内容"——这是 L1/L2 的分水岭。

## 6. L0/L1/L2 边界判定（最容易判错的 4 个场景）

| 场景 | 判定 | 计入？ | 说明 |
|---|---|---|---|
| 用户点"采纳/确认"没改任何字 | **L1** | ✅ 计入 | 按官方"无需人工**干预**"，确认不算干预 |
| 用户点"采纳"但顺手改了标点/格式/换行 | **L2** | ❌ 不计入 | ★争议点：改了产物实质内容，从严判 L2 |
| 用户觉得结果对，要求"重跑一次"得相同结果 | **L1** | ✅ 计入 | 规范明确：重跑得相同结果算 L1 |
| 用户补充了成分约束 / 上传了数据 / 改了代码 | **L2** | ❌ 不计入 | 实质接管 Agent 角色 |

**边界原则**：判定 L1 还是 L2，只看一句话——**用户是否改变了产物的实质内容**。只点按钮 = L1；动了内容 = L2。
**有疑议一律记 L2 + note 说明**，宁可保守，不美化自动完成率（评委最恨虚高）。

## 8. 异常处理

| 情况 | 处理 |
|---|---|
| 用户卡住不知怎么操作 | 只说"按你真实判断来"，**不引导**、不暗示预期 |
| 录屏中断 | 该子任务段重跑，或整批记为 M1b 重测 |
| 某 Agent 报错/空产物 | 该条记 **L2 + note"Agent 报错需人工接管"**，如实不遮掩 |
| 平台未自动拆解（直接给结果） | 记 note，该子任务 level 按用户实际干预判；若全程无拆解=产品缺陷，记明 |
| 用户主动说"这步我不会用" | 记 L2 + note，属真实干预 |

> 所有异常都**如实记录**，比"全程顺利"更受评委待见（呼应 R8 失败归因方法论）。
