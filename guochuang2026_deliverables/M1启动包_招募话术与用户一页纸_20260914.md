## 二、招募话术（直接复制发微信，不提 80%）

> 在忙吗？帮我个忙——我们在做一个"科研助手"的小工具，想找人实际用一下，看看顺不顺手。

**绝对不能说**："我们在测一个 ≥80% 的指标""尽量别改，改了我们就过不了"——一旦说了，数据就废了（偏倚）。

## 三、用户一页纸（★ 直接转发给受试者）

---

### 科研助手可用性测试 · 你要做的事

谢谢你来帮忙！很简单：**用我们的科研助手完成 10 个小任务，顺手记一下你做了什么。**

#### 你要准备
- 一台能上网的电脑，**30–60 分钟**不被打断
- 不需要专业知识，都是常见的科研小事（检索、清洗数据、画图、写段落…）

#### 每一步怎么做
1. 我给你一句任务（比如"检索高熵合金形成能 ML 预测的近三年综述"）
2. 你在助手里输入这句话，等它出结果
3. 拿到结果后，**按你平时的习惯来**——觉得能用就直接用、想改就改、觉得不对就让它重来
4. 然后**立刻**在记录表里写一句：你刚才实际做了什么

#### 三档，选一个填

| 你实际做了什么 | 填这个 |
|---|---|
| 全程没动，结果直接能用 | **L0** |
| 只点了"确认/采纳/通过"，没改内容 | **L1** |
| 改了内容、让它重跑、或打回重来 | **L2** |

> 类比：外卖到了直接吃 = L0；打开看一眼说"行"再吃 = L1；尝一口太咸自己回锅 = L2。

#### 两道"长链"题（第 7、8 题）
这两题是 **5 步串联**的（比如"选题→查文献→清洗→出图→写成段"），请**一步一步做**，**每一步都单独记一次**。

#### 请记住
- 按**真实习惯**操作，不用配合我们，也不用追求"让它全对"
- 记录是**匿名**的（用代号），你随时可以退出
- 有任何卡住、看不懂、不放心的地方，直接在"备注"写一句——这些对我们最有用

## 四、达标边界预警（这个你必须心里有数）

你的协议第五节定了：**长链 = 每步 (L0+L1) 比例连乘**；整条链按 1 题计。10 题 = 8 单步 + 2 长链。

| 情形 | 总体率 | 达标？ |
|---|---|---|
| 全过（含两条长链每步都过） | 100% | ✅ |
| 一条长链崩 | 90% | ✅ |
| 两条长链都崩、单步全过 | **80%** | ⚠️ 刚好压线 |
| 两条长链崩 + 单步错 1 个 | **70%** | ❌ |

**结论：单步任务一个都不能错（容错 0），长链每步至少 96%**（0.96⁵≈81.5% 整链才过）。

**这是本次测试最大的风险点**——长链恰恰最能证明"多 Agent 协同"，但也最容易因一步 L2 整条崩。跑之前先确认：长链每一步的交接（Schema/中间结果）是否稳定；不稳就先补路由再测。

## 五、测完立刻做（A + agent）

1. 算主数字：`(L0+L1)/总题数`
2. 出分层：按 Agent 类型、单步 vs 长链、长链各步连乘
3. **诚实列 L2 清单**（哪些题/哪个用户/为什么返工）—— 答辩加分项
4. 若 <80%：定位 L2 集中环节 → 补该 Agent 的 Schema/路由 → 复测，闭环进 v0.3
5. **留档**：原始记录表 + 截图 + 录屏（录屏同时是演示视频素材，强烈建议开）

> 若只有 2 个用户（n=2），如实标注 n=2，别凑数。宁可 n 小，不要假数据。
